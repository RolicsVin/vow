# Export To Obfuscate

Аддон обфусцирует идентификаторы GDScript при экспорте проекта. Поддерживает
два режима.

## Как работает

1. Во время экспорта Godot передаёт аддону каждый файл.
2. Для GDScript-файлов аддон сохраняет исходный текст во временный файл и
   запускает `py/obfuscate.py` (теперь он внутри аддона) через Python из
   Python Bridge или системный Python.
3. В полном режиме так же обрабатываются `.tscn`/`.tres` файлы — в них
   обновляются ссылки на переименованные имена.
4. При успешной обработке подменяет экспортируемый файл обфусцированной
   версией.

Файлы проекта не изменяются. Временные файлы удаляются после обработки.

## Режимы

Режим выбирается в **Project Settings → Export To Obfuscate → Mode**
(`export_to_obfuscate/mode`): `safe` или `full`. По умолчанию — `safe`.

### Безопасный режим (`safe`)

Поведение не изменилось по сравнению с прежней версией аддона.

Переименовываются:
- параметры функций;
- локальные переменные, объявленные через `var` или `const`;
- переменные циклов `for`.

Не изменяются:
- имена классов, функций, сигналов и свойств класса;
- переменные с `@export`;
- имена методов и свойств API Godot;
- строки, комментарии и типы в аннотациях.

### Полный режим (`full`)

Дополнительно, **согласованно по всему проекту**, переименовываются:
- имена функций (кроме служебных колбэков движка, см. ниже);
- переменные класса — `var`/`const`, в том числе `@export` и `@onready`,
  публичные и приватные;
- сигналы.

Одно и то же исходное имя получает один и тот же новый идентификатор во всех
файлах проекта, поэтому обращения вида `node.method_name()`,
`obj.some_var`, `emit_signal("signal_name")`, `has_method("method_name")`
остаются согласованными. `.tscn`/`.tres` файлы тоже обновляются:
- свойства узла, соответствующие переименованной переменной подключённого
  к нему скрипта;
- `signal="..."` и `method="..."` в секциях `[connection]`.

Что **никогда** не переименовывается в полном режиме:
- имена классов (`class_name`, `extends`);
- стандартные виртуальные колбэки движка (`_ready`, `_process`,
  `_physics_process`, `_input`, `_notification`, `_get`, `_set` и т.п.) —
  Godot вызывает их по фиксированному имени;
- частые встроенные свойства/сигналы узлов (`position`, `visible`, `text`,
  `value`, `pressed`, `timeout`, `body_entered` и похожие) — если в проекте
  объявлено собственное имя, случайно совпадающее с одним из них, оно тоже
  оставляется без изменений, чтобы не сломать обращение к ЧУЖИМ узлам с таким
  же встроенным свойством/сигналом в другом месте проекта.

Если какое-то из зарезервированных по умолчанию имён в вашем проекте
переименовывать безопасно (у вас нет конфликтов) — такой автоматики нет,
обфускация в этом случае просто немного консервативнее. А если наоборот —
какое-то **ваше собственное** имя нужно гарантированно защитить от
переименования (например внешний код/плагин дергает его по строке), добавьте
его в `export_to_obfuscate/full_mode_extra_reserved_names`.

Если при сканировании находятся имена, совпадающие с частыми встроенными
свойствами/сигналами, аддон выводит предупреждение в вывод редактора со
списком таких имён.

## Настройки проекта

- `export_to_obfuscate/mode` — `safe` (по умолчанию) или `full`.
- `export_to_obfuscate/full_mode_exclude_dirs` — папки, которые полный режим
  не сканирует и не переименовывает. По умолчанию `res://addons` (чтобы не
  затронуть сторонние аддоны и сам ExportToObfuscate).
- `export_to_obfuscate/full_mode_extra_reserved_names` — дополнительные имена
  функций/переменных/сигналов, которые полный режим никогда не должен
  переименовывать.

## Требования

- Godot 4.7+.
- Python 3.
- Для Windows можно использовать интерпретатор из
  `addons/python_bridge/runtime/windows/python.exe`.
- При необходимости путь к Python задаётся в настройке
  `python_bridge/editor_interpreter`.

## Ограничения

Это усложняет чтение извлечённых скриптов, но не является шифрованием и не
защищает от восстановления логики. Обфускация не заменяет проверку
целостности, шифрование PCK и защиту критической логики на стороне сервера.

Дополнительно для полного режима:

- Переименование основано на точном совпадении имени по всему проекту, а не
  на анализе типов. Если ваш собственный `var`/`func`/`signal` называется
  так же, как встроенное свойство/сигнал/метод Godot (сверх списка,
  зарезервированного по умолчанию), обращение к ЧУЖОМУ узлу с тем же
  встроенным именем в другом месте проекта теоретически может сломаться.
  При конфликте — переименуйте свой символ в проекте или добавьте его в
  `full_mode_extra_reserved_names`.
- Переменные вложенных классов (`class Foo: ...` внутри файла) не
  переименовываются.
- Переопределения экспортированных свойств для *инстанцированных* дочерних
  сцен (когда сцена-родитель хранит собственное значение поверх сцены-
  инстанса, а не скрипт назначен напрямую в этом же `.tscn`) не
  обрабатываются — такое переопределение в этом случае будет молча
  проигнорировано Godot (используется исходное значение по умолчанию), а не
  вызовет ошибку.
- Перед релизом рекомендуется проверить экспортированную сборку в полном
  режиме и просмотреть предупреждения в выводе редактора во время экспорта.

## История изменений

### 2.0.1

Исправлены три бага, из-за которых экспортированная в полном режиме игра
могла не запускаться ("Identifier ... not declared", "Nonexistent function"):

- `"%s" % value` (форматирование строк) ошибочно распознавалось как `%NodeName`
  (обращение к уникальному узлу), и `value` не переименовывалось — при этом
  его объявление уже было переименовано. Теперь `%` правильно различается как
  бинарный оператор и как префикс уникального узла по контексту слева от него.
- Параметры со значением по умолчанию (`func foo(x = 5)`) не переименовывались
  в заголовке функции, но переименовывались в теле — это баг, унаследованный
  из прежней (безопасной) версии обфускатора, воспроизводится в обоих режимах.
  Заодно исправлено смежное поведение: ключи словарных литералов
  (`{a = 1, b = 2}`) теперь не переименовываются независимо от позиции ключа
  (раньше это работало только для не первого ключа).
- Полный режим применял переименование по общей карте проекта ко ВСЕМ
  `.gd`-файлам при экспорте, включая файлы из `full_mode_exclude_dirs`
  (по умолчанию — все аддоны). Настройка исключений учитывалась только при
  сканировании, но не при применении карты, из-за чего код стороннего аддона
  мог быть переименован, если в нём случайно встречалось имя, совпадающее с
  именем из вашего проекта. Теперь файлы из исключённых папок всегда
  обрабатываются только локально (как в безопасном режиме), без применения
  общей карты.
